Bare-metal firmware that controls the speed of a **DC motor** via **PWM** on Timer0, with a **potentiometer** read through the ADC as the speed reference. A transistor drives the motor from a separate 12 V supply. ADC readings are smoothed with a simple **IIR filter** and mapped to the PWM duty cycle. Part of my embedded firmware collection built with **PlatformIO**, simulated in **Proteus** (no physical hardware).

---

## ✨ Features

- ✅ Bare-metal C (no Arduino framework)
- ✅ Timer0 in **Fast PWM** mode on OC0A (PD6)
- ✅ ADC0 (PC0) reads the potentiometer as speed reference
- ✅ **IIR low-pass filter** (`(x*7 + new)/8`) to smooth the ADC readings
- ✅ **Dead-zone** below duty ~6 % to stop motor jitter at low setpoints
- ✅ Separate 12 V motor supply via transistor (no load on the MCU)
- ✅ Target: ATmega328P @ 8 MHz

## ⚙️ How it works

1.  **ADC setup (`adc_init`):** `REFS0` selects AVcc as reference. Prescaler = 128 (`ADPS2|ADPS1|ADPS0`) → ADC clock = 8 MHz / 128 = 62.5 kHz (within the 50–200 kHz recommended range). A dummy conversion is performed and discarded to prime the sample-and-hold circuit.
2.  **PWM setup:** `TCCR0A = COM0A1 | WGM01 | WGM00` enables **Fast PWM** with non-inverting output on OC0A (PD6). `TCCR0B = CS01 | CS00` sets prescaler = 64 → PWM frequency = 8 MHz / 64 / 256 ≈ **488 Hz** (audible but fine for a small DC motor).
3.  **Main loop:**
    - `adc_read()` triggers a conversion and returns the 10-bit result (0–1023).
    - The reading is fed into an **IIR filter**: `filtered = (filtered * 7 + reading) / 8`. This is a first-order low-pass with α = 1/8 — cheap and effective at removing jitter.
    - `pwm_val = filtered >> 2` maps 10-bit (0–1023) → 8-bit (0–255) for `OCR0A`.
    - **Dead-zone:** if `pwm_val < 15` (≈ 6 % duty), force 0 so the motor stays off at the low end of the pot instead of buzzing.
    - `OCR0A = pwm_val` updates the duty cycle.

## 📚 Key registers / values

| Register | Value                             | Purpose                      |
| -------- | --------------------------------- | ---------------------------- |
| `ADMUX`  | `REFS0`                           | AVcc reference, channel ADC0 |
| `ADCSRA` | `ADEN \| ADPS2 \| ADPS1 \| ADPS0` | Enable ADC, prescaler 128    |
| `TCCR0A` | `COM0A1 \| WGM01 \| WGM00`        | Fast PWM, non-inverting OC0A |
| `TCCR0B` | `CS01 \| CS00`                    | Prescaler 64                 |
| `OCR0A`  | 0–255                             | Duty cycle                   |

## 🚀 Build and simulate

```bash
pio run          # Generates the .hex
```

`platformio.ini`:

```ini
[env:ATmega328P]
platform = atmelavr
board = ATmega328P
framework = arduino
board_build.f_cpu = 8000000L
```

1.  Open the `.pdsprj` file in Proteus.
2.  Double-click the MCU and set **Clock Frequency** to 8 MHz (must match `F_CPU`).
3.  Load the `.hex` generated by PlatformIO into program memory.
4.  Run the simulation — turn the potentiometer and watch the motor speed change (use a DC motor with an encoder/oscilloscope probe to visualize the PWM).

## 📝 Notes & limitations

- **Proteus DC motor model** is simplified — the simulated speed response is not the same as a real motor's inertia and torque curve.
- **No closed-loop control:** the firmware is open-loop (pot → duty). Real speed regulation would need encoder feedback and a PI(D) controller.
- **PWM frequency ≈ 488 Hz** is in the audible range; many small DC motors whine at this frequency. Increasing the prescaler (or switching to Timer1 at 16-bit) would move it out of hearing.
- **Freewheeling diode is essential** on real hardware to protect the transistor from the motor's back-EMF — included in the Proteus schematic for completeness.
- **ADC filter is IIR α = 1/8** — smooth but slightly sluggish. Lower α = smoother/slower, higher α = faster/noisier.
- **12 V supply must share GND with the 5 V MCU supply** — easy to miss when simulating.
- Troubleshooting quick-ref:
  - Motor doesn't spin → check transistor orientation, base resistor, and that PD6 is actually toggling.
  - Motor spins at full speed regardless of pot → ADC channel/pin mismatch or wiper not connected.
  - Motor jitters at low pot positions → increase dead-zone threshold.
  - Speed jumps around → increase IIR smoothing (lower α).
- **Future improvements:** direction control with an H-bridge (L298N / DRV8871), closed-loop speed control with an encoder, soft-start ramp, LCD readout of duty cycle.
