Bare-metal driver for a **16×2 HD44780 character LCD** in **4-bit mode** on the ATmega328P. Part of my embedded firmware collection built with **PlatformIO**, simulated in **Proteus** (no physical hardware).

---

## ✨ Features

- ✅ Bare-metal C (no Arduino framework)
- ✅ HD44780 in **4-bit mode** (6 pins instead of 10)
- ✅ Reusable driver split into `lcd.h` / `lcd.c`
- ✅ Full init sequence per the **HD44780U datasheet**
- ✅ Direct register manipulation (`DDRD`, `PORTD`)
- ✅ API for positioning, display flags, screen shifting and number printing
- ✅ Configurable pin mapping via macros (`LCD_PORT`, `LCD_DDR`, `LCD_RS`, `LCD_E`)

## ⚙️ How it works

1.  **Initialization:** `lcd_init()` configures PD0–PD5 and runs the 4-bit init sequence from the datasheet (0x03, 0x03, 0x03, 0x02) + function set, display on, clear and entry mode.
2.  **Nibble sending:** `lcd_send_nibble()` puts 4 bits on PD2–PD5 and pulses `E` to latch them.
3.  **Byte writing:** `lcd_write_byte(rs, data)` sets RS and sends the byte as two nibbles (high first).
4.  **Positioning:** `lcd_goto(row, col)` computes the DDRAM address (`0x00`/`0x40` + `col`) and sends `0x80 | addr`.
5.  **Number printing:** `lcd_print_uint/int/hex/float()` convert digit by digit — no `sprintf`, keeping flash usage low.

---

## 📚 Public API

| Function                         | Description               |
| -------------------------------- | ------------------------- |
| `lcd_init()`                     | Initializes in 4-bit mode |
| `lcd_write_byte(rs, data)`       | Sends command or data     |
| `lcd_goto(row, col)`             | Positions the cursor      |
| `lcd_print(const char *)`        | Prints a string           |
| `lcd_print_uint/int/hex/float()` | Prints numbers            |

## 📝 Notes & limitations

- Simulation only; not validated on real hardware.
- `lcd_print_float()` uses a custom implementation (no `sprintf`).
- `E` timings and waits follow the datasheet; may need tuning on real hardware.
