Bare-metal firmware that simulates a **traffic light** (red → green → yellow) on PORTD with a **countdown timer** shown on a single 7-segment display driven through a **74HC595 shift register**. The phase state machine and countdown are handled by **Timer1 in CTC mode** (1 Hz interrupt), while the main loop only refreshes the display when needed. Part of my embedded firmware collection built with **PlatformIO**, simulated in **Proteus** (no physical hardware).

---

## ✨ Features

- ✅ Bare-metal C (no Arduino framework)
- ✅ **3-phase traffic light** state machine (red 9 s → green 9 s → yellow 3 s)
- ✅ Countdown displayed on a 7-segment display via **74HC595 shift register**
- ✅ **Timer1 CTC** at 1 Hz for phase timing
- ✅ Non-blocking main loop — only refreshes the display on `display_dirty`
- ✅ Table-driven phases via `struct` array
- ✅ Target: ATmega328P @ **16 MHz**

## ⚙️ How it works

1.  **Pin setup:** PD0–PD2 as outputs (traffic LEDs), PB0–PB2 as outputs (shift register data/clock/latch).
2.  **Timer1 setup:** CTC mode (`WGM12`), prescaler 256 (`CS12`), `OCR1A = 62499`. At 16 MHz this gives:
    ```
    16,000,000 / 256 = 62,500 Hz tick rate
    62,500 / (62499 + 1) = 1 Hz  →  1 s per interrupt
    ```
    `OCIE1A` enables the compare-match interrupt.
3.  **Phase state machine:** `phases[]` is a table of `{light_mask, duration}`. `apply_phase(idx)` turns off all traffic LEDs, applies the phase's mask, resets `seconds_left`, and flags the display for refresh.
4.  **ISR (`TIMER1_COMPA_vect`):** every 1 s, if `seconds_left > 1` it decrements; otherwise it advances to the next phase (`current_phase = (current_phase + 1) % 3`) and calls `apply_phase()`.
5.  **`shift_out(data)`:** bit-bangs a byte into the 74HC595 LSB-first, then pulses the latch (`SLACH_PIN`) to copy the shift register to the output register.
6.  **Main loop:** only does work when `display_dirty` is set. It compares `seconds_left` to the last value sent and, if changed, shifts the new digit's segment pattern out. Otherwise it does nothing — no blocking, no busy-wait.

| Phase | Light  | Duration |
| ----- | ------ | -------- |
| 0     | Red    | 9 s      |
| 1     | Green  | 9 s      |
| 2     | Yellow | 3 s      |

## 📚 Key registers

| Register | Value           | Purpose                         |
| -------- | --------------- | ------------------------------- |
| `TCCR1A` | `0`             | Normal port operation           |
| `TCCR1B` | `WGM12 \| CS12` | CTC mode, prescaler 256         |
| `OCR1A`  | `62499`         | 1 Hz compare match @ 16 MHz     |
| `TIMSK1` | `OCIE1A`        | Enable Timer1 compare interrupt |

## 🚀 Build and simulate

```bash
pio run          # Generates the .hex
```

`platformio.ini`:

```ini
[env:ATmega328P]
platform = atmelavr
board = ATmega328P
framework = arduino
board_build.f_cpu = 16000000L
```

1.  Open the `.pdsprj` file in Proteus.
2.  Double-click the MCU and set **Clock Frequency** to **16 MHz** (must match `F_CPU`).
3.  Load the `.hex` generated by PlatformIO into program memory.
4.  Run the simulation — the traffic light cycles and the 7-segment counts down each phase.

## 📝 Notes & limitations

- **`TICKS_PER_SEC` is defined but unused** — the macro is declared but the ISR assumes 1 tick = 1 s directly. Either remove the macro or multiply durations by it for clarity.
- **`shift_out()` blocks for ~16 µs** (8 bits × 2 µs). Acceptable, but a hardware SPI version would be faster and free up the CPU.
- **`volatile` on `current_phase`, `seconds_left`, `display_dirty`** is correct — they're shared with the ISR.
- **No race protection** on `display_dirty` between ISR and main. In practice the 1-byte write is atomic on AVR, so it's fine, but worth knowing.
- **`_delay_us(1)` in `shift_out()`** assumes `F_CPU` matches the Proteus clock — if you ever change one without the other, the 74HC595 may latch garbage.
- Troubleshooting quick-ref:
  - Display shows nothing → check 74HC595 OE is grounded, latch wiring correct.
  - Countdown runs at 2× or 0.5× speed → `F_CPU` ≠ 16 MHz or Proteus clock ≠ 16 MHz.
  - Wrong digit shown → verify `seven_seg[]` bit order matches 74HC595 → segment mapping.
  - Traffic LEDs don't cycle → check `TIMSK1`/`sei()` and that `apply_phase(0)` runs before the loop.
- **Future improvements:** pedestrian button to request a crossing phase, blinking green before red, multi-digit countdown via daisy-chained shift registers, hardware SPI for the 74HC595.
